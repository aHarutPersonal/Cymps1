# Встроенная практика: реализация и проверка

Сервер и Flutter-интерфейс реализованы локально. Новая практика открывается из читателя и через кнопку «Practice & finish». Производственная база и сервер не обновлялись.

Следующим этапом добавлена [передача результатов практики в будущие уроки](PRACTICE_ADAPTATION.md), различие прохождения с поддержкой и без подсказки приложения и соответствующее пояснение на фронтенде. Числа тестов ниже относятся к исходной реализации практики.

Объём: рабочая практика внутри Flutter-читателя и соответствующий API. Поддержать числовые поля и таблицы, выбор ответа, письменное объяснение, схематические геометрические фигуры. Существующие уроки служат источником задания; новый запрос не должен придумывать другую методологию наставника.

1. Описать строгую схему задания: данные, поля, критерии, подсказка, решение и перенос. Правильные ответы хранятся на сервере.
2. Хранить практику по пользователю, уроку и версии содержания; сохранять черновик, версии ответов, подсказки и результаты проверок. Защитить повторные запросы и конфликтующие сохранения.
3. Генерировать комплект один раз при подготовке практики. Числа и варианты проверять детерминированно; объяснения оценивать отдельным ограниченным запросом по рубрике. Не засчитывать сбой проверки как успех.
4. Добавить рабочую область в читатель: исходные данные, ввод, автосохранение, подсказка, обратная связь, исправление и новое задание. Учитывать маленький экран, клавиатуру и тёмную тему.
5. Связать завершение с принятыми обязательными заданиями для уроков с включённой практикой. Сохранить возможность открыть уже завершённые старые уроки.
6. Проверить схемы, арифметику, сокрытие решений, привязку к пользователю и версии, повторную отправку, сбои, сохранение и Flutter-интерфейс. Подготовить миграцию; производственную базу и развёртывание не менять в рамках локальной реализации.

Проверка моделью даёт обратную связь по заданным критериям, а не гарантию истины. Сохранённые попытки позволяют отличать ответ после подсказки от самостоятельного. Эта реализация не заменяет последующий учебный пилот и не обещает измеренную длительность уроков.

## Что работает

- Числовые поля, наборы расчётов с единицами, один выбранный вариант и свободное письменное объяснение.
- Геометрические схемы из подписанных точек и соединяющих отрезков; все размеры задаются текстом и данными. Это схема, не редактор свободного рисования и не измерительный инструмент.
- Черновик с автосохранением, сохранением при выходе и уходе приложения в фон. Несохранённые изменения явно обозначены. Сбой загрузки не отбрасывает локальный ввод. Автономное сохранение после принудительного закрытия приложения без сети не реализовано.
- Последовательные задания: практика, обратная связь, исправление, новый кейс для переноса. Можно открыть текст урока рядом с работой.
- История попыток, конкретная обратная связь по полям, подсказки и отложенное раскрытие решения. Завершённая практика сохраняется для просмотра и не перезаписывается.
- Числа проверяются серверным вычислением разрешённой арифметики; варианты — по сохранённому ключу. LLM оценивает письменную часть по критериям. Неопределённая оценка и сбой проверки не дают успешного результата.

## Серверный контракт

Таблица `lesson_practices` хранит владельца, урок, хеш содержания вместе с идентичностью артефакта, приватный комплект заданий, ответы, попытки, подсказки и ревизию. Ключи решений не входят в обычный ответ API. Первое обращение к подготовке создаёт комплект; последующие используют сохранённую версию. Библиотека общих заданий между пользователями — отдельный этап большой архитектуры, а не свойство этого персонального кеша.

Операции находятся под `/plan-items/{item}/steps/{step}/practice`: чтение, `prepare`, `draft`, `submit`, `hint`. Чтение не вызывает LLM. Сохранение использует ревизию; повторная отправка того же ответа не вызывает повторную платную оценку. Долгие операции имеют аренду исполнения, освобождают транзакцию перед запросом к модели и повторно проверяют версию перед записью результата. Подготовка ограничена тремя попытками, проверки — сорока вызовами на комплект, включая неудачные проверки.

Все новые публикации уроков в основном задании генерации получают `practice_required`. И завершение отдельного урока, и общее завершение миссии проверяют практику на сервере. Для старой версии требование также включается при первом запуске подготовки; старые завершённые уроки не переоцениваются автоматически. Новый читатель проводит пользователя через практику независимо от возраста урока.

Оценки времени у упражнений пока редакционные. Из читателя и карточек уроков убрано вычитание времени чтения из общего бюджета для получения якобы измеренного времени практики. Старые серверные расчёты недельной нагрузки и нормализатор длительности остаются отдельной задачей из основного исследования.

## Проверки

Сервер: 362 теста практики, завершения, последовательности, промптов, подготовки недели и схем урока прошли. Миграция успешно скомпилирована в PostgreSQL SQL без применения к базе. Проверки схем, API и поведения используют локальные фикстуры; реальная конкурентная работа на PostgreSQL и живые ответы модели ещё не испытаны.

Flutter: 27 тестов практики, читателя и репозитория прошли; статический анализ семи затронутых файлов завершился без замечаний. Проверяются автосохранение, ввод во время сохранения, сбой сети, восстановление, исправление, переход к следующему кейсу, узкий тёмный экран, просмотр урока, завершение через читатель и сохранение при выходе. Для визуальной проверки используется настоящий Flutter-виджет с учебными данными; в [тестовом снимке](practice-screen.png) шрифты заменены локальным Roboto, чтобы не скачивать их во время теста. Схема и подписи проверены визуально.

2. Выполнить несколько реальных подготовок и проверок по математике, инвестиционному кейсу и аргументации; проверить соответствие решений, объяснений и рубрик, а также задержку и фактический расход.
3. Выпустить совместимую Flutter-сборку. Старые клиенты не имеют рабочего экрана практики, поэтому новый серверный обязательный режим требует координации обновления приложения.

В рамках этой работы миграция, развёртывание и платный предметный пилот не запускались. Полный переход на общую библиотеку блоков, долговременную модель освоения навыков и отложенные проверки остаётся в [общем контракте](IMPLEMENTATION_CONTRACT.md).
