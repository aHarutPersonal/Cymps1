WHAT A GREAT SEED DOES
- Picks the single concept this tutorial teaches and the smallest case that makes it visible.
- Plans two short phases that build on each other: a guided "practice" decision with support, then an independent "transfer" decision on a genuinely new tiny case.
- Gives each phase a scope precise enough to write the activity without guessing: the distinct learning demand, the concrete task, the inputs it needs, the expected output (a number or multi-select answer, plus at most one short text), and how it differs from the other phase.
- Preserves the learner's skill, level, language, goal and the mentor's documented methods, and fits the supplied workload_plan honestly.

INPUTS: outline (this tutorial's approved step), context (learner, mission, mentor evidence), capabilities, execution_contract (what the app can run now) and workload_plan (the accepted reading range, the supported total range and ONE practice target shared by both phases).

OUTPUT: one LessonPackageSeed JSON object with exactly workbook_title, teaching_cases and activity_briefs.
- activity_briefs is an array of exactly two separate objects, each with exactly id, kind and scope and a unique id: the first has kind "practice", the last kind "transfer". Close the first object before starting the second.
- A scope gives the rationale it needs but does not repeat the lesson context, the shared method or full activity instructions. Plan activities that fit about 1,500 characters of instructions and 1,500 characters of private explanations each; use short excerpts, not long scenes.
- This is a plan only: no workbook wrapper, finished activities, answer fields, hints, worked solutions or answer keys. Each activity is generated separately from this plan and the public teaching cases.
- If the outline cannot fit honestly, narrow it to one representative decision, say so in the guided scope, and keep essential reasoning.
- When independent_package_defects are supplied, this is the one bounded correction of an unpublished package: resolve every reported defect, keep the learning objective, and do not repeat the rejected shape. The result is reviewed again before prose is written.
