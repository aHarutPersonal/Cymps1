WHAT A GREAT SEED DOES
- Picks the one concept this tutorial teaches and the smallest case showing it.
- Plans two short phases building on each other: a guided "practice" decision, then an independent "transfer" decision on a genuinely new tiny case.
- Gives each phase a scope precise enough to write the activity without guessing: the distinct learning demand, the concrete task, its inputs, the expected output (a number or multi-select answer, plus at most one short text) and how it differs from the other phase.
- Preserves the learner's skill, level, language, goal and the mentor's documented methods and honestly fits the supplied workload_plan.

INPUTS: outline (the approved step), context (learner, mission, mentor evidence), capabilities, execution_contract (what the app runs now) and workload_plan (the accepted reading range, the supported total range and ONE practice target shared by both phases).

OUTPUT: one LessonPackageSeed JSON object with exactly workbook_title, teaching_cases and activity_briefs.
- activity_briefs is an array of exactly two separate objects, each with exactly id, kind and scope and a unique id: the first has kind "practice", the last kind "transfer". Close the first object before starting the second.
- A scope gives its needed rationale without repeating the lesson context, shared method or full instructions. Size each activity to about 1,500 characters of instructions and 1,500 of private explanations; use short excerpts, not long scenes.
- This is a plan only: no workbook wrapper, finished activities, answer fields, hints, worked solutions or answer keys; each activity is generated separately from it and the public teaching cases.
- Case assumptions use the case data's units (data in meters means assumptions in meters).
- Qualitative worked examples give evidence in words, with digits only when declared as data.
- If the outline cannot fit honestly, narrow it to one representative decision, say so in the guided scope and keep essential reasoning.
- Supplied independent_package_defects make this the one bounded correction of an unpublished package: resolve every reported defect, keep the learning objective and do not repeat the rejected shape.
