Write ONE complete executable tutorial_v1 activity from its activity_brief and the public teaching context.

WHAT A GREAT ACTIVITY DOES
- Executes the brief with all inputs in its own instructions and data.
- Elicits the brief's skill with one question, two only if necessary. Reconstruct a rule or predict in the learner's own words. In method selection, withhold the correct method and deciding cue from titles, questions and public rubrics.
- Scaffolds guided practice; transfer leaves the assessed reasoning to the learner. Request an initial attempt before consulting the example, keep hints optional and treat immediate success as case-specific.
- Gives each field one substantive private explanation from raw facts, available after attempting: why the method fits, the misconception it resolves, each item's effect on its own and the net where items offset. It agrees with formulas and criteria; text includes a complete model answer.

INPUTS: outline, context, capabilities, execution_contract, public_seed (teaching cases, all briefs), your activity_brief, workload_plan and activity_workload (your position and an equal-share reference, never a minimum); other activities are generated independently.

OUTPUT: the LessonActivityDraft itself — id, title, kind, instructions, data, fields, hint, minutes_min, minutes_max and optional diagram.
- Keep activity_brief.id and kind exactly. Return no workbook, activity array, teaching cases, brief, patch, fragment, worked_solution, steps, version or field_id: the server builds the private solution from field explanations in order. hint and minutes belong to the activity, outside fields.
- data is always present and lists every raw number in the instructions, hint or explanations, including evidence for text or choice answers; it is [] only when there is none, so a qualitative worked example uses digits only as declared data. Structural list labels and timing fields are not case facts; derived results are never inputs.
- Each field is one complete object: id, label (the learner-visible question or requested response, not an internal id or criterion), kind, explanation and, except for text, rubric_criterion. Text adds 1-5 criteria; number an expression; choice 2+ choices and one correct_choice; multi_choice 2+ choices and correct_choices, the exact set to select, each option one atomic action whose label contains no other option's action. Use only that kind's properties; omit optional defaults, empty choices and null diagrams.
- rubric_criterion is the result-panel row: under 80 characters naming the skill a correct answer shows (for multi_choice, the skill the whole correct set shows), never the answer itself (text criteria too: both are public). A number field may add a prefix like "$" (the unit is the suffix) and up to three misconceptions: an expression over this activity's data ids for a plausible wrong answer, with 10-240 characters of feedback naming the mistake without the corrected value.
- Explanations total 40-4,000 characters, instructions at most 4,000; aim near 1,500 each.
- A question names any formula in words, never as a bare numeric expression. The activity hint and any optional field hint give the next reasoning step without the answer, restated instructions or a walkthrough; a field hint has no digit.
- minutes_min and minutes_max are this activity's honest share of doing, explaining, checking and one revision, not reading or overall target.
- Refer to answers by field label, not invented question numbers; write model answers as plain prose without "(1)" labels; a genuinely numbered learner task keeps its sequence.
