## YOUR OBJECTIVE

Generate a highly effective, 12-week strategic plan that transforms this user toward the level of {idol_name}. The plan MUST be deeply rooted in {idol_name}'s actual domain, methods, and trajectory — NOT generic self-help advice.

## CALIBRATE TO THE USER FIRST (READ BEFORE EVERYTHING BELOW)
The idol's milestones define the DESTINATION; the User Context, Readiness data, and gap analysis define the STARTING LINE and the PACE. Before applying any rule below, anchor the plan to where THIS user actually is:
- Set Week 1's difficulty to the user's current level, NOT the idol's peak. A beginner starts with fundamentals; do not open with idol-level challenges.
- Every week's total effort MUST fit within {hours_per_week} hours. Do not exceed it — an over-stuffed plan the user abandons is a failed plan.
- Apply exactly one task-count rule to every week:
  - **LOW-CAPACITY PLAN — under 6 hours/week:** exactly 1 mission task and exactly 1 daily rhythm task. Right-size both to fit the cap. The mission may be shorter than 2 hours as a low-capacity exception, but it must still have a substantial, binary deliverable and satisfy every specificity and description-depth requirement below.
  - **STANDARD PLAN — 6 hours/week or more:** 2-3 mission tasks and 1-2 daily rhythm tasks, with mission blocks of 2-8 hours and practice allocations sized to fit the same weekly cap.
- For a daily rhythm task, `estimated_hours` means its TOTAL weekly time across all repetitions, not one session. Let the runtime schedule its sessions and keep the total within {hours_per_week} hours.
- This conditional count rule is authoritative everywhere in this prompt. Never apply the standard counts to a low-capacity plan, and never emit a week whose total `estimated_hours` exceeds {hours_per_week}.
- If the User Context is rich, the plan must visibly reflect it. Do not let the idol's achievements crowd out the user's real situation, constraints, and stated goal ({user_goal}).

## NON-NEGOTIABLE RULES

### 1. DOMAIN-SPECIFICITY (most important rule)
Every task MUST directly relate to {idol_name}'s actual field of expertise. Use the idol's domain, themes, roles, and milestones as your guide.

- If the idol is a physicist (e.g., Einstein): tasks must involve physics, mathematics, scientific reasoning, thought experiments, reading original papers
- If the idol is an investor (e.g., Buffett): tasks must involve financial analysis, value investing, reading financial statements, understanding businesses
- If the idol is a founder (e.g., Jobs): tasks must involve product design, user experience, building things, understanding markets
- If the idol is a writer: tasks must involve writing, reading great literature, developing voice, publishing

NEVER generate generic tasks like "write your first article", "network with people", "build your brand" that could apply to anyone regardless of idol.

NOTE ON EXAMPLES: the Einstein/Buffett/Jobs examples throughout this prompt illustrate FORMAT and SPECIFICITY only. Never let their domains (physics, investing, product) leak into a plan for a different kind of idol — an athlete's plan trains like the athlete, a painter's plan paints. Derive every task from {idol_name}'s actual field.

### 2. SUBSTANTIAL MISSION TASKS (not micro-tasks)
Each MISSION task must represent real, focused work with a meaningful artifact or demonstrated skill. In a standard plan it takes 2-8 hours. Only the low-capacity rule above may shorten it, and that exception changes duration—not the 50-word description minimum, domain specificity, binary completion criterion, or quality of the deliverable.

- ❌ BAD: "Read a blog post about investing" (15 minutes, trivial)
- ❌ BAD: "Write down your goals" (5 minutes, not a real task)
- ✅ GOOD: "Read chapters 1-5 of 'Security Analysis' by Benjamin Graham and write a 1-page analysis of Graham's intrinsic value formula" (4-6 hours, substantive)
- ✅ GOOD: "Work through the first 20 problems in Spivak's 'Calculus' Chapter 1, proving each theorem yourself before reading the proof" (5-8 hours, skill-building)

For owner-earnings exercises, Buffett's 1986 shareholder letter is the primary
reference. Do not present net income plus depreciation minus total capital
expenditure as his complete definition. Maintenance spending and required
additional working capital involve judgment; supply case data and explicit
assumptions instead of inventing a precise company estimate. A method example
illustrates a learning activity, not a recommendation to trade a security.

### 3. MEANINGFUL DAILY RHYTHM TASKS (not trivial habits)
Practice routines consolidate taught skills inside the app. Prefer one anchor
routine. A second must serve a distinct purpose within the same weekly budget.
The runtime schedules Monday, Wednesday and Friday by default, splits weekly
minutes exactly, and lets the learner choose days and a starting cue. Do not
invent another schedule, daily requirement or fixed duration in prose.

For each routine, daily_instructions gives 70-120 actionable words connecting
this week's taught skill to an explicit If-Then implementation cue (when/where
to start and what single friction step to remove before opening the app), cold
recall of the governing rule and deciding cue in the learner's own words, an
attempt in the prepared review, checking, correction, and a specific error note.
The review reuses real exercises from
already attempted lessons with inputs, saved answers, hints and answer checks.
Do not claim a supplied dataset, example or key merely because you mention one.
No review appears before lesson practice has been attempted. Stop and save at
the session cap even if unfinished. Prior mistakes return across weeks. Known
cases check retention; new applications and transfer belong in mission practice.
Logging participation does not certify mastery. Do not promise push reminders.
Write all task titles, descriptions, and daily_instructions with natural human
sentence-length burstiness and concrete transitive verbs; avoid AI clichés
("delve", "tapestry", "testament", "crucial", "moreover", "not only... but also",
or "it's not about X, it's about Y").


### 4. SUBSTANCE MINIMUMS
- Every `description` for mission tasks (project/course/reading) MUST be at least 50 words with specific books, chapters, exercises, or techniques named. Generic descriptions like "Work on your goal" or "Study the fundamentals" are FORBIDDEN.
- Every `description` for daily rhythm tasks (habit/practice) MUST be at least 30 words with a specific, measurable action.
- Every `primary_mission` MUST be at least 30 words and reference a specific skill, deliverable, or outcome.

### 5. IDOL-SPECIFIC REFERENCES
Include specific resources that are:
- Books written BY the idol or considered foundational in their field
- Biographies or papers about the idol's actual methods
- Techniques the idol used (name them specifically)
- The idol's actual habits and routines only when supported by the supplied profile, persona, milestones,
  comparison, or blueprint. Otherwise recommend a domain-standard method without attributing it to the idol.

Never invent a quotation, chapter number, paper title, routine, date, or anecdote. If you know a real book
but are not certain about its chapter numbering, name the exact book and the concept/section to study rather
than guessing a chapter number.

Example for Einstein: reference "The Feynman Lectures on Physics", Einstein's 1905 papers, "Spacetime Physics" by Taylor & Wheeler, thought experiment methodology.
Example for Buffett: reference "The Intelligent Investor", Berkshire Hathaway annual letters, "Security Analysis" by Graham & Dodd.

### 6. BINARY MISSION TASKS
A mission task is either 100% complete or 0% complete. "Study physics" is vague. "Complete problems 1-15 in Chapter 3 of 'Classical Mechanics' by Goldstein and verify your answers" is binary and actionable.

### 7. TWO CATEGORIES OF TASKS
Every week MUST include BOTH:
- **Primary Mission tasks** (`type: "project"`, `"course"`, or `"reading"`): Major milestone tasks that get expanded into full sub-step lessons by the detail generator.
- **Daily Rhythm tasks** (`type: "habit"` or `"practice"`): Repeatable, self-contained actions the user sees on the home screen and checks off on the stated cadence.

The number and duration of each category MUST come from the single conditional task-count rule in CALIBRATE TO THE USER FIRST. Do not infer a second count rule from examples elsewhere.

### 8. RESOURCE HINTS MUST BE CANONICAL
When a task mentions a book, include the exact book title AND author. When referencing a video or course, include the creator/platform. These hints will become shared `content_resources`, so ambiguity creates duplicates.

### 9. ANTI-GOALS MUST BE DOMAIN-SPECIFIC
Anti-goals should identify real distractions specific to the idol's field:
- ❌ BAD: "Avoid procrastination" (generic, applies to everyone)
- ✅ GOOD: "Do NOT jump into advanced quantum mechanics before mastering classical mechanics and linear algebra — premature abstraction is the #1 killer of physics students"
- ✅ GOOD: "Do NOT chase hot stock tips or crypto — stick to understanding intrinsic value and reading annual reports"

### 10. USE THE GAP ANALYSIS
The gap analysis tells you exactly where the user is behind {idol_name}. Prioritize tasks that close the biggest gaps first. If the user is "beginner" in a category the idol excelled in, that category gets the most attention.

### 11. PROGRESSION STRUCTURE
The 12 weeks should follow a natural learning arc:
- **Weeks 1-3: Foundation** — Master prerequisites, build mental models, establish daily practice
- **Weeks 4-6: Core Skills** — Tackle the idol's primary domain skills, read foundational texts
- **Weeks 7-9: Applied Practice** — Build real things, solve real problems, create artifacts
- **Weeks 10-12: Integration** — Connect skills together, attempt idol-level challenges, reflect

Daily rhythm tasks should PROGRESS across weeks:
- Early weeks: simpler, shorter, foundational
- Middle weeks: more complex, longer, skill-building
- Late weeks: creative output, teaching others, synthesis

### 12. HYPER-PERSONALIZED
Use the User Context and Readiness data. Adapt difficulty to their level. If they're a beginner in the idol's domain, start with fundamentals — don't skip to advanced material.
